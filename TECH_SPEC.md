# TECH_SPEC — MebelFlow AI MVP

## 1. Цель

Создать white-label виджет для мебельного лендинга, в котором потенциальный клиент голосом или текстом формирует предварительное ТЗ прямой кухни.

## 2. Scope MVP

### Поддерживается

- одна прямая стена;
- ширина стены 1200–7000 мм;
- высота помещения 2200–4000 мм;
- нижний ряд;
- верхний ряд;
- антресоли;
- техника;
- текст и голос;
- SVG;
- опциональный 3D-вид принятых GLB-модулей;
- стиль;
- диапазон цены;
- заявка;
- PDF;
- tenant settings.

### Не поддерживается

- Г-образная кухня;
- П-образная кухня;
- остров;
- эркер;
- скосы;
- нестандартные радиусы;
- прямое открытие рабочих файлов SketchUp/PRO100;
- раскрой;
- деталировка;
- станки;
- фотореализм.

## 4. Стандартные ширины

Настраиваются tenant, значения по умолчанию:

```text
150, 200, 300, 400, 450, 500, 600, 700, 800, 900, 1000
```

Техника:

- ПММ: 450 или 600;
- духовой шкаф: 600;
- холодильник: 600 по умолчанию;
- стиральная машина: 600.

## 5. Высоты по умолчанию

- корпус нижней тумбы: 720;
- ножки/цоколь: 100;
- столешница: 38;
- итог нижнего ряда: 858, округляемая настройкой tenant;
- рекомендуемая рабочая высота: 860–920;
- фартук: 550–650;
- основные верхние шкафы: 720, 800, 900;
- минимальная антресоль: 400;
- потолочный зазор: 20–50.

## 6. Логика антресолей

```text
available = roomHeight
          - lowerTotalHeight
          - apronHeight
          - ceilingGap
```

Если антресоли включены:

```text
mainHeight + mezzanineHeight = available
mezzanineHeight >= tenant.minMezzanineHeight
mainHeight ∈ tenant.allowedUpperHeights
```

Движок выбирает:

1. точное стандартное сочетание;
2. ближайшее сочетание;
3. вариант с увеличенной антресолью;
4. предупреждение, если решение невозможно.

## 7. Голосовой ввод

### Требования

- кнопка записи;
- индикация;
- возможность остановить;
- транскрипт перед применением;
- команда применяется после подтверждения либо автоматически при высокой уверенности;
- пользователь может отменить.

### Поддерживаемые фразы

- «Высота потолка два семьдесят».

- «Верни предыдущий вариант».

## 8. Intent Parser

### Вход

```json
{
  "utterance": "после мойки поставь посудомойку 600",
  "locale": "ru-KZ",
  "projectSummary": {
    "wallWidth": 3000,
    "moduleIds": ["sink-1"],
    "remainingWidth": 2200
  }
}
```

### Выход

```json
{
  "commandId": "cmd_uuid",
  "type": "INSERT_AFTER",
  "referenceId": "sink-1",
  "payload": {
    "moduleType": "dishwasher_600",
    "width": 600
  },
  "confidence": 0.97,
  "needsConfirmation": false
}
```

### Низкая уверенность

```json
{
  "type": "CLARIFY",
  "question": "Вы хотите посудомойку шириной 450 или 600 мм?"
}
```

## 9. Layout Engine

### Обязательные проверки

- размер стены известен;
- ширина положительная;
- ширина разрешена;
- модуль существует;
- reference существует;
- сумма модулей не превышает стену;
- техника имеет допустимую ширину;
- положение не конфликтует;
- верхний ряд не превышает доступную высоту;
- антресоли не ниже минимума;
- добор не отрицательный.

### Остаток

```text
remaining = wallWidth - sum(moduleWidths)
```

Если остаток:

- 0–50: технологический зазор;
- 51–149: предложить добор;
- 150+: предложить модуль или несколько вариантов.

## 10. SVG Renderer

### Обязательные элементы

- пол;
- нижний ряд;
- столешница;
- фартук;

- размеры;
- подписи;
- выбранный модуль;
- предупреждения;

### Масштаб

SVG viewBox должен быть независимым от пикселей.

```text
scale = availableCanvasWidth / wallWidth
```

### Mobile

- горизонтальная прокрутка запрещена в стандартном сценарии;
- подписи должны сокращаться;
- детали открываются по tap;
- выбранный блок подсвечивается;
- редактирование — через диалог, не через сложные drag handles.

12. Сессия восстанавливается.

## 18. Stage 10 — Visual Asset Library и 3D viewer

### Назначение

Дать клиенту полноценный интерактивный WebGL-вид согласуемой компоновки: вращение 360°, zoom/pinch, панорамирование, выбор модуля и синхронизация с Project State. Это не CAD, не производство и не фотореалистичный рендер.

### Готовая цепочка подготовки

```text
SketchUp component
→ CleanUp³ / мебельные правила плагина
→ готовый GLB exporter
→ glTF Transform или gltfpack
→ Khronos glTF Validator JSON report
→ MebelFlow acceptance limits
→ accepted asset library
→ Three.js GLTFLoader
```

MebelFlow не создаёт собственные GLB-экспортёр, оптимизатор или валидатор. Собственный SketchUp-плагин отвечает только за мебельную семантику, выбор компонента и удаление заранее определённых служебных деталей.

### Минимальная запись каталога

- `assetId`, `moduleType`, номинальные `dimensionsMm`;
- `glbUrl`, `validationReportUrl`, SHA-256;
- byte size, triangle count, draw call count;
- использованные exporter/optimizer/validator;
- вычисляемый статус `accepted`.

GLB содержит стандартную glTF-сцену. Отдельный собственный JSON сцены запрещён. JSON рядом с GLB содержит только каталог и официальный validation report.

### Приёмка

- glTF 2.0 и ноль ошибок Khronos Validator;
- лимиты по размеру файла, треугольникам, draw calls и warnings;
- только root-relative или HTTPS URL;
- runtime получает только `accepted` записи;
- checksum проверяется ingestion-слоем перед сохранением (следующий backend-срез).

Начальные лимиты: 8 MiB, 150 000 треугольников, 120 draw calls, не более 20 предупреждений. Они версионируются после тестов на среднем Android.

### Runtime и UX

- SVG — default и обязательный fallback;
- Three.js — отдельный lazy chunk;
- OrbitControls: rotate, pan, wheel и pinch zoom;
- GLTFLoader загружает только URL из принятого каталога;
- выбор синхронизируется по `sourceModuleId`;
- отказ WebGL, timeout или повреждённый GLB не блокирует возврат к SVG;
- box-геометрия допустима только как технический fallback, не как заявленный итоговый 3D.

### Следующие срезы

1. Backend ingestion: upload GLB/report, checksum, object storage, audit.
2. Offline pipeline scripts вокруг glTF Transform и Khronos Validator.
3. Каталог/поиск модулей по типу и номинальным размерам.
4. SketchUp plugin adapter для мебельной семантики.
5. Android performance budgets и реальные подготовленные модели.

## 19. Interface Design Skill

Для всех клиентских UI-задач обязателен локальный навык:

```text
skills/mebelflow-conversational-interface/SKILL.md
```

Он применяется при:

- проектировании widget;
- реализации voice/text flow;
- отрисовке SVG;
- создании прогресса;
- выборе стиля;
- отображении цены;
- обработке ошибок;
- клиентском подтверждении;
- UI review.

### Дизайн-направление

**«Спокойная мастерская»**

Интерфейс должен ощущаться:

- профессиональным;
- тёплым;
- тактильным;
- понятным;
- спокойным;
- современным;
- не похожим на generic AI dashboard.

### Постоянные зоны widget

1. Progress Header.
2. Conversation Area.
3. Scheme Stage.
4. Context Action Bar.
5. Status Line.

### Обязательные UI-принципы

- одно основное действие на экран;
- голос и текст равноправны;
- транскрипт видим;
- интерпретация команды прозрачна;
- схема обновляется немедленно;
- undo всегда доступен после изменения;
- не более трёх рекомендаций;
- progressive disclosure;
- цена только как диапазон;
- disclaimer до заказа и PDF;
- ошибки сохраняют состояние;
- touch targets минимум 44×44;
- WCAG 2.2 AA;
- reduced motion;
- обязательная проверка 360×800.

### UI Definition of Done

UI-функция не завершена без:

- mobile screenshot;
- desktop screenshot;
- keyboard pass;
- accessibility smoke;
- slow network state;
- error/empty/offline state;
- visual regression;
- review по трём столпам:
  - Frictionless;
  - Quality Craft;
  - Trustworthy.

# ADR-005: Принятые GLB-модули и ленивый Three.js viewer

**Статус:** Accepted
**Дата:** 2026-08-06
**Заменяет часть решения:** ADR-002 в части полного запрета 3D-файлов

## Контекст

Владелец продукта утвердил Stage 10 для полноценного пространственного просмотра и будущей библиотеки готовых мебельных модулей. Модели ещё не созданы. Изобретать собственный формат, экспортёр и оптимизатор не требуется: экосистема glTF уже закрывает эти задачи.

## Решение

- SketchUp остаётся источником модели, но рабочий `.skp` не загружается в MebelFlow.
- Очистка: CleanUp³ плюс узкие мебельные правила собственного плагина.
- Экспорт: готовый GLB exporter.
- Оптимизация: glTF Transform либо gltfpack.
- Стандартная валидация: Khronos glTF Validator и его JSON report.
- MebelFlow добавляет только проектные acceptance limits и каталог метаданных.
- Runtime: Three.js GLTFLoader + OrbitControls.
- SVG остаётся default; 3D загружается лениво по явному действию.
- Scene Engine видит только записи `accepted`; произвольные URL и непроверенные файлы запрещены.

## Не входит

- собственный формат 3D-сцены;
- собственный glTF validator/optimizer/exporter;
- редактирование полигонов в браузере;
- CAD и производственные операции;
- фотореалистичный рендер;
- автоматическое определение мебельной семантики по имени файла.

## Последствия

Появляется независимая библиотека модулей и интеграционный ingestion-слой. Three.js не входит в основной bundle. Ошибка 3D не должна блокировать диалог, SVG, цену или заявку. Реальные лимиты окончательно принимаются после Android-теста с подготовленными GLB.
